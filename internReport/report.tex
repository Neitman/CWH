\section{PHẦN 1: GIỚI THIỆU}

\subsection{Phát biểu bài toán và công việc được giao}

Nhu cầu xem video cùng nhau giữa những người dùng ở các vị trí địa lý khác nhau (Co-watching / Xem video nhóm) ngày càng phổ biến. Tuy nhiên, các nền tảng video hiện tại chủ yếu phục vụ cá nhân hóa theo từng phiên đơn lẻ. Việc đồng bộ phát video thủ công (đếm ngược 3-2-1 để bấm Play) gặp hạn chế lớn về sai lệch độ trễ mạng ($2s - 10s$) và làm mất tính tương tác thời gian thực khi có người tạm dừng video để thảo luận.

\textbf{Công việc được giao trong đợt thực tập:}
Nhiệm vụ trọng tâm là nghiên cứu và xây dựng ứng dụng Web thời gian thực cho phép đồng bộ hóa trạng thái phát video nhóm với độ trễ siêu thấp ($<1s$). Các mục tiêu cụ thể gồm:
\begin{enumerate}[leftmargin=1.2cm]
    \item Đăng ký, đăng nhập tài khoản an toàn với mã hóa mật khẩu và token xác thực.
    \item Khởi tạo phòng xem và tham gia phòng thông qua Mã phòng (Room ID) duy nhất.
    \item Đồng bộ tức thời các thao tác: Phát (Play), Tạm dừng (Pause), Tua (Seek), Chuyển bài trong danh sách phát (Queue).
    \item Tích hợp hệ thống trò chuyện (Chat) gắn mốc thời gian xem video (Timestamp).
\end{enumerate}

\subsection{Khảo sát công nghệ, công cụ và lý do lựa chọn}

\subsubsection{Truyền thông thời gian thực: HTTP Polling vs WebSocket}
\begin{itemize}[leftmargin=1.2cm]
    \item \textbf{HTTP Polling:} Client gửi request liên tục để kiểm tra dữ liệu. \textit{Nhược điểm:} Tạo ra lượng dữ liệu dư thừa lớn (HTTP Header overhead $500B-2KB$/request), gây quá tải CPU/RAM máy chủ và độ trễ cao ($1s-5s$).
    \item \textbf{WebSocket (Socket.IO):} Duy trì kênh truyền thông song công toàn phần (Full-duplex) trên 1 kết nối TCP duy nhất. \textit{Ưu điểm:} Overhead cực nhỏ ($2B-10B$), độ trễ siêu thấp ($<100ms$), Server chủ động push dữ liệu. Thư viện Socket.IO hỗ trợ tự động kết nối lại và quản lý Room thông minh.
\end{itemize}

\subsubsection{Xác thực và Bảo mật: Session-Cookie vs JWT + Bcrypt}
\begin{itemize}[leftmargin=1.2cm]
    \item \textbf{Session-Cookie:} Stateful, phụ thuộc bộ nhớ phiên Server, khó mở rộng và khó truyền xác thực khi kết nối WebSocket từ domain khác.
    \item \textbf{JWT (JSON Web Token) + Bcrypt:} Stateless, chữ ký số HMAC-SHA256 bảo mật. Token được đính kèm dễ dàng trong REST Header và WebSocket Handshake (`socket.handshake.auth.token`). Bcrypt băm mật khẩu chống tấn công vét cạn.
\end{itemize}

\subsubsection{Backend \& Cơ sở dữ liệu: Node.js, PostgreSQL và Redis}
\begin{itemize}[leftmargin=1.2cm]
    \item \textbf{Node.js \& TypeScript:} Event Loop bất đồng bộ (Non-blocking I/O) xử lý hàng ngàn kết nối WebSocket đồng thời với bộ nhớ RAM thấp.
    \item \textbf{PostgreSQL \& Redis (ioredis):} PostgreSQL lưu trữ bền vững thông tin tài khoản, phòng xem và lịch sử tin nhắn. Redis lưu trữ In-memory siêu tốc ($<1ms$) cho trạng thái phát thời gian thực (`isPlaying`, `progress`, `lastUpdated`).
\end{itemize}

\subsection{Triển khai các Module chức năng}

\subsubsection{Module Xác thực và Quản lý phòng xem}
\begin{itemize}[leftmargin=1.2cm]
    \item \textbf{REST API Auth:} Xây dựng các route đăng ký, đăng nhập và middleware `authenticateToken` giải mã JWT Token trong Header `Authorization: Bearer <token>`.
    \item \textbf{WebSocket Handshake Auth:} Khi thiết lập kết nối socket, Server lấy token từ `socket.handshake.auth.token` để xác thực danh tính người dùng và phân nhóm socket vào Room tương ứng qua lệnh `socket.join(roomId)`.
\end{itemize}

\subsubsection{Module Đồng bộ Video và Thuật toán Bù sai lệch}
\begin{itemize}[leftmargin=1.2cm]
    \item \textbf{Khắc phục vòng lặp sự kiện (Event Loop Feedback Loop):} Khi Client nhận lệnh đồng bộ từ Server và gọi API trình phát (`seekTo`, `pauseVideo`), sự kiện `onStateChange` tự động bật làm gửi ngược sự kiện lên Server. Hệ thống sử dụng cờ `isSyncing = true` tại Client để tạm thời bỏ qua phát sự kiện trong $300ms$.
    \item \textbf{Thuật toán bù sai lệch thời gian (Drift Compensation):} Khi người dùng mới tham gia phòng, Server tính thời gian video đã phát bằng công thức:
    $$\text{progress} = \text{progress\_gốc} + \frac{\text{Thời gian hiện tại} - \text{lastUpdated}}{1000}$$
    từ dữ liệu lưu trong Redis.
\end{itemize}

\subsubsection{Module Trò chuyện nhóm thời gian thực}
Server lắng nghe sự kiện `send-discussion-message`, trích xuất `videoTimestamp` hiện tại, lưu tin nhắn vào PostgreSQL và phát sự kiện `new-discussion-message` cho toàn bộ thành viên trong phòng.

\begin{enumerate}[leftmargin=1.2cm]

\subsubsection{Phân tích lỗi kỹ thuật và Cách khắc phục}
\begin{enumerate}[leftmargin=1.2cm]
    \item \textbf{Lỗi vòng lặp sự kiện vô hạn:} Gọi lệnh API trình phát kích hoạt lại sự kiện `onStateChange`. \textit{Khắc phục:} Sử dụng cờ cản `isSyncing` tạm khóa gửi tin nhắn lên Server trong $300ms$.
    \item \textbf{Lỗi trôi thời gian phát (Time Drift):} Thời gian phát cố định khiến người vào sau bị lệch pha. \textit{Khắc phục:} Thuật toán Drift Compensation tự động tính thời gian trôi qua dựa trên `lastUpdated` lưu trong Redis.
    \item \textbf{Lỗi rò rỉ tệp tin rác trên đĩa:} Video tự tải lên không bị xóa khi bỏ khỏi Queue. \textit{Khắc phục:} Xây dựng hàm `cleanupCustomVideoFile()` xóa tệp tin bằng `fs.unlinkSync()` ngay khi gỡ bài.
    \item \textbf{Lỗi Token JWT hết hạn:} Ngắt kết nối kết nối WebSocket giữa chừng. \textit{Khắc phục:} Đăng ký handler `auth-error` hiển thị thông báo và chuyển hướng đăng nhập lại.
\end{enumerate}

    \item \textbf{Bài học kinh nghiệm:} Nâng cao tư duy thiết kế hệ thống thời gian thực bất đồng bộ, kết hợp PostgreSQL \& Redis và kỹ năng phân tích nguyên nhân lỗi kỹ thuật.
\end{itemize}

\section*{KẾT LUẬN}

\begin{itemize}[leftmargin=1.2cm]

\subsection*{Phụ lục B: Cấu hình môi trường và Cài đặt}
\begin{enumerate}[leftmargin=1.2cm]
    \item Khởi chạy Postgres \& Redis: \texttt{docker compose up -d}
    \item Khởi chạy Backend Server: \texttt{cd backend \&\& npm install \&\& npm run dev}
    \item Khởi chạy Frontend Client: \texttt{cd frontend \&\& npm install \&\& npm run dev}
\end{enumerate}
